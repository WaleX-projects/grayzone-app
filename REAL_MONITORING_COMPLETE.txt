                        HOW IT WORKS NOW
================================================================================

COMPLETE FLOW:

1. User opens Grayzone
   └─ MainActivity launches
   └─ ServiceManager.startMonitoringService() called

2. UsageTrackingService starts (Foreground)
   ├─ Shows "Grayzone - Monitoring app usage" notification
   └─ Initializes MonitoringManager

3. MonitoringManager runs monitoring loop continuously
   (Even if user closes Grayzone!)
   
   Every 5 seconds:
   ├─ ForegroundAppDetector: Which app is active?
   ├─ If monitored app (e.g., TikTok):
   │  ├─ Query UsageStatsManager for real usage
   │  ├─ Check: usage >= configured threshold?
   │  └─ If YES:
   │     ├─ Check: Already intervened in last 5 minutes?
   │     └─ If NO: Trigger intervention
   └─ If not monitored: Continue checking

4. When Intervention Triggered:
   ├─ GrayzoneNotificationManager.showInterventionNotification()
   ├─ InterventionActivity launches (full-screen, non-dismissible)
   └─ Shows: "Hold on. You've been using TikTok for X minutes."
        "What would you like to do?"
        [Continue using TikTok] [Take a break]

5. User Chooses:
   ├─ Continue → Back to TikTok (can intervene again in 5 minutes)
   └─ Take a break → Can review app usage in Grayzone

6. Service Continues:
   └─ Monitoring loop resumes, checking every 5 seconds

================================================================================
                       LIFECYCLE MANAGEMENT
================================================================================

Service Startup:
  1. MainActivity.onCreate() called
  2. ServiceManager.startMonitoringService() called
  3. If service not running, UsageTrackingService.start() called
  4. Service starts with notification
  5. MonitoringManager loop begins

Service During App Lifecycle:
  - onCreate: Start service (if not already running)
  - onPause: Service continues
  - onResume: Check if service still running, restart if needed
  - onDestroy: Service continues (not destroyed with app)

Service Persistence:
  - START_STICKY flag ensures restart after system kill
  - Service can't be killed by app manager (foreground service)
  - Will restart if system kills it
  - Service continues monitoring indefinitely

Recovery:
  - MainActivity.onResume() checks service health
  - If service crashed, it's automatically restarted
  - No user action needed

================================================================================
                      THROTTLING MECHANISM
================================================================================

Why Throttle?
  - Prevent spam notifications
  - Allow time for actual app usage
  - Reduce battery drain
  - Provide realistic experience

How It Works:
  - First intervention at 1 minute: Shows immediately
  - User continues or takes break
  - Next intervention not before: 1 minute + 5 minutes = 6 minutes
  - This prevents rapid-fire interventions

Example:
  0:00 - Start TikTok
  1:00 - Intervention #1 (triggered, throttle timer starts)
  1:30 - Tap "Continue"
  2:00 - Use TikTok again
  2:00 - Intervention would trigger but: too soon (< 5 min since last)
  6:00 - Enough time passed
  6:00 - Intervention #2 can trigger now

Implementation:
  - MonitoringManager tracks: Map<app, lastInterventionTime>
  - Before triggering, checks: now - lastTime > 5 minutes?
  - Only triggers if sufficient time has passed
