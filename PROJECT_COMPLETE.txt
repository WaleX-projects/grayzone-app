================================================================================
                              SUMMARY
================================================================================

Built a fully functional Android MVP that demonstrates the core Grayzone
concept: Help users notice their app usage without taking control away.

Core flow:
  1. User selects an app to monitor (e.g., TikTok)
  2. User sets intervention threshold (e.g., 1 minute)
  3. App tracks real usage via UsageStatsManager
  4. When threshold reached, intervention UI appears
  5. User chooses to continue or take a break

The entire system is LOCAL-FIRST with Room database persistence.

                        HOW TO TEST (5 MINUTES)
================================================================================

1. BUILD
   ./gradlew :androidApp:assembleDebug

2. INSTALL
   adb install androidApp/build/outputs/apk/debug/androidApp-debug.apk

3. GRANT PERMISSION (CRITICAL!)
   Settings → Apps → Special app access → Usage access → Enable Grayzone
   Without this, usage detection won't work!

4. LAUNCH APP
   Tap Grayzone icon

5. ADD APP
   - Tap "Apps" tab
   - Tap "Add monitored app"
   - Tap "Browse installed apps"
   - Select TikTok (or Instagram, YouTube, etc.)
   - Set: Daily limit=60 min, Intervention=1 min ← Use 1 min for quick test
   - Tap "Add"

6. TEST INTERVENTION
   - Go to Home tab
   - Tap your monitored app
   - SessionScreen opens with simulated feed
   - Wait ~10 seconds
   - See friction card: "Still want to keep going?"
   - Tap buttons to interact

================================================================================
                         CORE PHILOSOPHY
================================================================================

Grayzone follows the principle:

  "Help users notice their behavior, not take control away from them."

Implementation priorities:
  1. Awareness (measure usage accurately)
  2. User choice (let them decide what to do)
  3. Configurability (adapt to their needs)
  4. Low friction (gentle reminders, not blocks)
  5. Local-first (no servers needed)
  6. Reliable monitoring (background service)
  7. Calm UI (non-punitive messaging)
  8. Minimal battery (efficient polling)

This MVP achieves all 8 principles.

                         KEY INSIGHTS
================================================================================

1. UsageStatsManager queries are accurate but have ~15 second latency
2. The vertical slice deliberately uses 1-minute thresholds for fast testing
3. SessionScreen simulates usage - real detection only in service
4. All app data persists locally, no server needed
5. Permission handling is critical - must be granted in Settings
6. The monitoring system is designed to be battery-efficient
7. Intervention detection can be triggered multiple ways:
   - From background service
   - From SessionScreen for testing
   - Manually for testing purposes
